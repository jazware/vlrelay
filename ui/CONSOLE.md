# Operator console

The console at `/admin` and the public page at `/` share one look, "exchange": a switchboard at night. Bone and ink-indigo panels, cobalt for action, a magenta carrier lamp for the live stream (seq, commit, emit), Archivo widened for labels and IBM Plex Mono for numbers. The shell is the vlpds console's (`vlpds/ui/CONSOLE.md`): a top bar with the carrier rule, a patch-panel rail of sections, a dense main column and one slide-over for any row. The kit was copied from there and re-skinned, so the two consoles drive the same way.

## Building a section

1. Replace the section's `case` in `route()` (`AdminApp.tsx`) with your page. Keep the old paths in `aliases` (`sections.tsx`) so links keep landing.
2. Start with `<PageHead>`, then `<Banners>` if anything needs attention, then `<HealthLine>` or `<Tiles>`, then panels in `cx-grid2` / `cx-stack`.
3. A row with more to show opens in the slide-over: register a detail kind with `registerDetail` and give the table `open={(row) => ({ type, id })}`. `o` and "Full page ↗" go to `/admin/<section>/<type>/<id>`.
4. Anything that changes the relay goes through `confirmAction` with the exact request in `call` (a function of the fields when they change it). No mock actions: call the endpoint through the adapter and let the dialog show the error.
5. Add entities and verbs to ⌘K with `registerPalette`.
6. Check it at 390 px and in both themes, against `admin_demo` and a real relay, with the browser console clean.

The kit's parts are documented in the vlpds CONSOLE.md. What differs here:

- `DataTable serverSort={{ id, asc, sortable, onSort }}` for tables the server sorts and pages (Hosts). Duplicate row keys get a suffix instead of breaking React.
- Wide tables don't spread their columns apart. One column takes the spare width: a name, a note or a description (`fill: true` on a `Col`, or `th.fill`/`td.fill` in a hand-built table), or, for a few narrow columns, an empty one at the end (`DataTable fit`). A full-width panel uses its spare width for a description column where it has one (the tier matrix, requests by purpose, by key).
- `Knob` (`Policy.tsx`) is the settings row: the label and why in a column of at most 400 px, then the control and its default beside it. Knobs in a full-width panel go in `<div className="cx-knobs">`, two to a row where there's room. A form's text input keeps to a sensible width (`flex: 0 1 440px`) beside its button.
- A policy number (`NumIn`) reads grouped at rest ("50,000,000"), as exact binary bytes ("200 MiB") or as "no limit" for a 0 that means none, and shows the raw value while focused. It takes "50M", "50,000", "200 MiB" and "no limit" (`parseNum`).
- A tile's second figure (`sec`) wraps under the value on a narrow tile instead of being cut off.
- `seriesOf(key)` (`queries.ts`) is a series the console builds from its own answers: the stream's rate, the commit latency, each busy host's rate, each consumer's rate, bucket requests per second. The busiest hosts' rates come from `overview.topHosts[].history`. It fills in while the page is open.
- `useStore` keeps `GET store`'s rates as `store-a` and `store-b`. `useQuorum` keeps what the statuses only have as counters: `requestRates()` (bucket requests per second over the last minute, by purpose, component and op, summed over the members that answer, and each member's own in `byNode`), `seenEpochs()` (the epoch moving, for a change no member's history lists) and `flushSeenAt()`. They start empty on each page load.
- `useQuorumHistory` is `GET cluster/quorum/history`; `epochEvents` (`quorumUi.tsx`) joins it with the statuses' `switches` and `recovered`: each lead becomes a takeover, handoff, membership change or recovery, and a step-down belongs to the next epoch's lead (or stands alone while nobody leads).
- The Discovery page edits the policy's `discovery` section through the one policy draft (`DiscoveryPolicy` and `DraftBar` come from `Policy.tsx`), so a seed relay added there is reviewed and saved as any policy change. The review lists the seed relays one line per relay.
- The gate (`AdminApp.tsx`) asks `GET session` without a token first. When a proxy in front of the admin listener named the operator (docs/admin-api.md, "Sign-in through a proxy"), the console opens with no token, calls carry no `Authorization`, the top bar says "as <login>" and Lock console goes away. `useAdminUnlock()` is the gate's state, `useAdminOperator()` the login.
- `NeedsVersion what endpoint` stands in for a panel whose endpoint isn't there yet (below).
- `Over r detail` (`kit.tsx`) is a value against its limit: the ratio as the headline ("6.7×"), the value and limit muted beside it, and a bar on one log scale from 0.1× to 10× with a tick at 1×, so a bigger overage always draws longer. Cases, the case drawer's trips and the spam signals use it.
- `seqSeenAt()` (`queries.ts`) is when the console last saw the newest seq move, to within a poll: Consumers' stream freshness.
- `recent.ts` keeps the last six details opened in the tab (`sessionStorage`, beside the token), written by the slide-over and the full page; `attention()` (`relayUi.tsx`) turns the banners' notices into palette items. Together they are ⌘K's empty-query inbox.
- `currentLead`, `recentLeaderChange` and `leaderChangeText` (`quorumUi.tsx`) say who leads since when and word a change for the Overview banner (30 minutes), the Quorum leader tile and ⌘K.

## Data

Every panel reads one TanStack Query cache (`lib/console/cache.ts`, provided in `main.tsx`), so the drawer, the tables, the tiles, the banners and the badges show one copy of each thing.

- **Queries.** `queries.ts` has a hook per thing the console shows (`useOverview`, `useHostList(q)`, `useHostDetail(name)`, `useCases`, `useRules`, `usePolicySource` …), each on a structured key from `keys` (`['host', name]`, `['hosts', query]`, `['policy', 'full']`, `['cases', status]`, `['case', id]`, `['consumers']`, `['cluster']`, `['quorum', 'status']` …). A one-off read is `useLive(key, fetch, opts)`. Each returns `{ data, error, loading, at, live, reload }`, which `Loaded` takes. Outside React, `cached(key)` reads what a key holds (palette providers, dialogs).
- **Polling.** `poll` is for live numbers no event announces (rates, lag, the series): the overview and the quorum every 2 s, host lists and consumers every 5 s. `fallback` is for what the change feed covers (policy, rules, cases, takedowns, accounts, discovery, the PLC export, the leadership history): it polls only while the feed is down. Space pauses every poll, and what went stale meanwhile is refetched on resume.
- **The change feed** (`feed.ts`, opened by the shell while the console is unlocked) reads `GET changes` with fetch, resumes with `Last-Event-ID` and reconnects with backoff. `applyChange` (`cache.ts`) turns each change into the keys it touches (`keysFor`): its entity, its lists, and the aggregates that count it (the overview, the banners' host lists, the tier counts, the host drawer's cases and rule). A `host` change patches the row from its hint at once, and refetches the lists only when its status or tier moved, so a busy relay's host changes don't refetch every list each second. An id of `*` refetches the kind, and a `resync` refetches everything shown. A 404 means an older relay: the console polls until a reload. The top bar's chip says which: live, reconnecting or polling.
- **Writes** (`writes.ts`) put their answer into the cache at once (a host action's row, which reads its own write, the rule, the case, the account, discovery with the run requested, the saved policy), then invalidate the same keys a change for them would. A host action answered `pending` (the cluster hadn't confirmed it within 3 s) shows "applying…" in the host's header until a change for it arrives. Pages never call a write endpoint on the adapter directly.
- **Versions.** A host row (`version`, node-scoped), the rule set (`version`), the policy (`version`), a case (`updatedAtMs`) and the cluster (`lastSeq`) never go back to an older copy: an answer older than the cached one is dropped (`compareVersions`, where two that don't compare count as new), and a change at or below the cached version is a replay and does nothing. Host rows are reconciled into `['host', name, 'row']`, the copy the drawer reads, and a list or detail that moves a host's state spreads it to every other copy. A host event from the host's owner (the row's `node`) carries the owner's live status in `hint.status`, and it stands over a fetched row until the row's `ownerVersion` (how much of the owner the answering node has heard, in the owner's counter) reaches the event's version.
- **Freshness.** `Updated` (`kit.tsx`) is the one "updated 4s ago": "live" while the feed keeps that data current, "paused" under space, a warning when the last refresh failed. Every page head and every drawer foot has one.
- **Status words** take their tone from `tone.ts` (host status, case severity and status, account status, consumer state), so a status looks the same on every page: `HostStatusChip` everywhere a host's status shows, backpressure always ◆ info.

## The adapter and what the backend lane owes

`lib/console/adminAdapter.ts` is the one place the console calls the admin API. An endpoint the design assumes but the relay doesn't serve answers `{ supported: false, endpoint }` through `missing(...)` without a request, so the browser console stays clean and the page shows a "needs a newer vlRelay" placeholder; `MISSING` in the same file lists them. `ops/rejects/top` is served now; a relay older than it answers the first request with a 404 (one line in the network log per page load) and the console doesn't ask again until a reload.

| Endpoint | Feeds | State |
| --- | --- | --- |
| `GET ops/rejects/top?reason=<reason>&limit=10` → `[{host, rejectsPerSec, total, lastAtMs, sample?}]`, cluster-wide | Hosts with `?reason=` (the Overview's reject bars): the hosts sending that reject | Served. `rejectsTop` in the adapter; "needs a newer vlRelay" on an older relay |

Found while building this, for the backend lane:

- `cases` has no paging or bulk write. The console fetches every case and pages them itself, and a bulk status change is a POST per case. A relay with thousands of open cases would want `cases?status=&kind=&limit=&offset=` (with counts by status and kind) and `POST cases/bulk {ids, status, note}`.
- `store`'s p50 and p99 are the upper bound of the histogram bucket each falls in, so the console shows them as "≤ 410 ms". Interpolated quantiles, or the bucket counts, would let it show a closer figure.
- `policy/usage` is the answering node's: `newAccountsPerMin` counts on the leader only, so from a follower the Policy page says it's counted on the leader instead of showing 0.
- `admin_demo`: its statuses carry no `flush.recent` or `history` (its `cluster/quorum/history` does), `takedowns` doesn't list a takedown made through the demo, and its discovery sources don't follow the policy's `discovery` section.
- `admin_demo` serves no `subscribeRepos`, so the tail says the firehose isn't reachable there. `npm run dev` proxies `/xrpc` (websockets too), so the tail works against a real relay.
- The console's own tail is a consumer: it shows in the consumer list with the browser's user agent.

## Keyboard

`⌘K` palette: on an empty query, what needs attention (each banner's notice, opening its row) and the last six details opened in this tab, then a pointer to type for the rest; typing finds sections, hosts by name, a DID or handle, nodes, verbs on a host (`ban …`, `suspend …`, `unban …`, `throttle …`, `reconnect …`, `raise cap …`), `run discovery` (all, or one source) and `add seed relay <url>` (into the policy draft). `g` then a letter jumps to a section (`g u` is the public page). `j` / `k` move through rows, `Enter` opens, `o` goes full page, `Esc` closes. `/` focuses the page's search, else the palette. `space` pauses live updates, `t` toggles the theme, `?` lists all of it.

## Trying it

```bash
cargo run --bin admin_demo                    # :2790, token "demo"
cd ui && npm run dev                          # :5790, proxies /admin/api, /api/public and /xrpc
```

A real relay with a tail and real actions: `fakepds run --hosts 5 --dids 200 --rate 150 --plc-port 29999 --lag-secs 60 --fault badsig:4:rate=0.4`, then `vlrelay --listen 127.0.0.1:2980 --memory --plc-url http://127.0.0.1:29999 --admin-token <token>` with a `--host http://127.0.0.1:3000N` per fakepds host, and `VLRELAY_URL=http://127.0.0.1:2980 npm run dev`.

## Look

- Status is a colour and a glyph, always both: `ok ●`, `warn ▲`, `err ■`, `info ◆`, `idle ○`.
- Cobalt (`--accent`) is for action, magenta (`--signal`) only for the live stream (the seq, the commit, the firehose line, the lit jack) and for the unsaved policy draft, which isn't live yet.
- The fonts are self-hosted in `public/fonts` (the page CSP allows no other origin).
- Use example.com-style names in fixtures and placeholders, and show what the server says (its hostname is the page's own). The docs and UI are public.
